# 第 7 課:狀態機 ─ 行人穿越號誌路口(C 版)

## 這個範例做什麼
做一個**按鈕式行人號誌**:平常車道綠燈,行人按下按鈕申請過馬路後,號誌依序走完
「車道黃燈 → 行人通行 → 行人綠燈閃爍催促 → 全紅淨空 → 回到車道綠燈」。

重點不在號誌本身,而在**怎麼組織程式**:這一課用**有限狀態機 (FSM)** 取代
「一堆 `delay()` 的無窮迴圈」,並把決策邏輯抽成**完全不碰硬體**的純邏輯。

## 檔案分工

| 檔案 | 內容 | 給誰編譯 |
|------|------|----------|
| [`fsm.h`](fsm.h) | 狀態、事件、輸出的定義與介面 | 兩邊都用 |
| [`fsm.c`](fsm.c) | **狀態機本體(純邏輯,零硬體相依)** | SDCC **和** gcc |
| [`main.c`](main.c) | 硬體層:Timer0 產生 tick、按鈕去彈跳、點 LED、UART 印紀錄 | 只有 SDCC |

同一份 `fsm.c` 會被三個地方編譯:燒進晶片、在電腦上模擬、在電腦上做單元測試。

## 🖥 沒有硬體?先在電腦上跑模擬器
這一課**不需要開發板也能完整學會**:

```bash
make -C ../../tools/fsm_sim run     # 或在專案根目錄:make sim
```

模擬器會用 5 個場景餵入不同的輸入(不按、晚按、早按、亂按、放大看閃爍),
把每一次「事件 → 處理結果 → 狀態 → 燈號輸出」畫成表格與時間軸:

```
   時間  | 事件 | 處理結果 |   狀態   | 車道燈| 行人| 嗶
  -------+------+----------+----------+-------+-----+----
    1.0s | 按鈕 | 記下請求 | 車道綠燈 | - - G | R - | -
         ↳ 行人請求登記了,但要等綠燈滿 5 秒才會動作
    5.0s | 時間 | 狀態轉移 | 車道黃燈 | - Y - | R - | -

  時間軸(每格 0.5 秒)  G=車道綠 Y=車道黃 W=行人通行 F=行人催促 R=全紅
    GGGGGGGGGYYYYYYWWWWWWWWWWWWWWWWFFFFFFFFFFRRRRGGGGG
      ^
```

跑單元測試(30 項,含「兩邊絕不同時綠燈」的安全不變式):

```bash
make -C ../../tools/host_test test
```

## 接線(5 顆 LED + 1 顆按鈕)
```
  車道紅燈  P1.0 ----[ 220Ω ]---->|---- GND
  車道黃燈  P1.1 ----[ 220Ω ]---->|---- GND
  車道綠燈  P1.3 ----[ 220Ω ]---->|---- GND
  行人紅燈  P1.6 ----[ 220Ω ]---->|---- GND
  行人綠燈  P1.4 ----[ 220Ω ]---->|---- GND

  行人按鈕  P1.5 ----[ 按鈕 ]---- GND        (內部弱上拉,按下讀到 0)
  蜂鳴器    P0.4 ---- 有源蜂鳴器 ---- GND    (選用)

  UART      P0.6 (TXD) ----> USB-TTL RX
            GND        ----> USB-TTL GND     (務必共地)
```
- 💡 **LED 不夠?** 只接「行人綠燈 P1.4 + 按鈕 P1.5 + UART」就看得懂流程,
  其餘燈號看 UART 的文字紀錄即可。
- 完整零件表與腳位總表:[`../../docs/09-硬體接線與零件表.md`](../../docs/09-硬體接線與零件表.md)

## 編譯與燒錄
```bash
make        # 編譯 main.c + fsm.c,產生 main.hex
make flash  # 燒錄到 N76E003
make clean  # 清除編譯產物
```

> `c/common.mk` 先把 `fsm.c` 編成 `fsm.rel`,再和 `main.c` 一起連結。

## 預期結果
1. 開機:車道綠燈亮、行人紅燈亮,UART 印出歡迎訊息。
2. 按下按鈕:
   - 若綠燈**還不到 5 秒**,UART 印 `[按鈕] 記下請求 -> 車道綠燈`,燈不變;
     等綠燈滿 5 秒,才自動切到黃燈。
   - 若綠燈**已滿 5 秒**,按下的瞬間就切到黃燈。
3. 之後自動跑完:黃燈 3 秒 → 行人綠燈 8 秒(慢「嗶」)→ 行人綠燈閃爍 5 秒
   (急促「嗶」)→ 全紅 2 秒 → 回到車道綠燈。
4. 流程中再按按鈕,UART 會印 `忽略事件`,號誌不受干擾。

UART 輸出範例(9600 8N1):
```
=== N76E003 行人穿越號誌 (狀態機範例) ===
按下 P1.5 的按鈕來申請過馬路
[開機] 狀態轉移 -> 車道綠燈
[按鈕] 記下請求 -> 車道綠燈
[時間] 狀態轉移 -> 車道黃燈
[時間] 狀態轉移 -> 行人通行
[按鈕] 忽略事件 -> 行人通行
[時間] 狀態轉移 -> 行人催促
[時間] 狀態轉移 -> 全紅淨空
[時間] 狀態轉移 -> 車道綠燈
```

## 程式重點
- **三層架構**:輸入層(ISR 去彈跳 → 事件)→ 狀態機(純邏輯)→ 輸出層(驅動腳位)。
- **只有一個地方會改 `state`**:`fsm_handle()` 裡的 `switch`。規則有單一出處。
- **輸出是狀態的純函式**:`fsm_outputs()` 給同樣的狀態一定得到同樣的燈號。
- **守衛條件 (guard)**:`m->request && m->ticks >= T_VEH_GREEN_MIN` 兩個條件同時成立才轉移。
- **主迴圈不阻塞**:沒有任何 `delay()`,所以隨時都能反應按鈕。
- 原理、與無窮迴圈架構的優缺點對照、狀態圖:[`../../docs/11-狀態機.md`](../../docs/11-狀態機.md)

## 為什麼這一課沒有組語版?
前 6 課每課都有 `asm/` 對照版,因為那些課在教**硬體周邊怎麼設定**(SFR 操作),
組語與 C 幾乎逐行對應,對照起來收穫很大。

這一課教的是**程式架構**,不是新的硬體。狀態機在組語裡要靠跳躍表(jump table)
手工實作,會把焦點從「架構觀念」拉回「指令細節」,反而失焦。
硬體操作部分(Timer0、GPIO、UART)在 [`asm/03-timer`](../../asm/03-timer/) 與
[`asm/04-uart`](../../asm/04-uart/) 都已經有組語版可以對照。
> 想挑戰的話,docs/11 §11.12 有「用組語實作狀態機」的提示。

   (`main.mem` 裡的 CODE 數字)。
