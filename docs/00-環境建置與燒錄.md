# 第 00 章:環境建置與燒錄

> 這一章把「寫程式 → 編譯 → 燒進晶片」這條路打通。做完一次,之後每一課都只要 `make flash`。
> 本教材的環境以 **Linux(Fedora)** 為例,其他發行版指令大同小異。

---

## 0.1 我們需要哪些工具?

| 工具 | 做什麼 | 本教材怎麼裝 |
|------|--------|-------------|
| **SDCC** | C 編譯器,也含組譯器 `sdas8051`、連結器 `sdld`、`packihx` | Homebrew 或發行版套件 |
| **nuvoprog** | 把編譯好的 `.hex` 透過 Nu-Link 燒進 N76E003 | 用 Go 編譯 |
| **make** | 自動化編譯流程 | 系統內建 |

硬體:**N76E003 開發板**、**Nu-Link 燒錄器**(本教材用 Nu-Link1 ICE)、USB 線。

---

## 0.2 安裝 SDCC

SDCC 一套就包含了 C 編譯器 **和** 組譯器,兩種語言都靠它。

**用 Homebrew(本教材採用,不需要 root):**
```bash
brew install sdcc
```

**或用發行版套件:**
```bash
# Fedora
sudo dnf install sdcc make
# Debian / Ubuntu
sudo apt install sdcc make
```

裝好後確認:
```bash
sdcc --version        # 應顯示 4.x
which sdas8051 sdld packihx
```

---

## 0.3 安裝 nuvoprog(燒錄工具)

nuvoprog 是用 Go 寫的,需要先有 `go` 和 `libusb`。

```bash
# 1) 安裝 go 與 libusb(擇一方式)
brew install go libusb            # 或： sudo dnf install golang libusb-devel

# 2) 編譯安裝 nuvoprog
go install github.com/erincandescent/nuvoprog@latest
```

編譯出來的執行檔會放在 `~/go/bin/nuvoprog`。把這個目錄加進 PATH(加到 `~/.bashrc` 或 `~/.zshrc`):
```bash
export PATH="$PATH:$HOME/go/bin"
```

> 💡 若 `go install` 時出現找不到 libusb 的錯誤,補上這些環境變數再試(路徑依你的 libusb 安裝位置調整):
> ```bash
> export CGO_ENABLED=1
> export PKG_CONFIG_PATH=/home/linuxbrew/.linuxbrew/lib/pkgconfig
> export CGO_CFLAGS="-I/home/linuxbrew/.linuxbrew/include/libusb-1.0"
> export CGO_LDFLAGS="-L/home/linuxbrew/.linuxbrew/lib -lusb-1.0"
> ```

確認:
```bash
nuvoprog --help
```

## 0.4 設定 USB 權限(udev 規則)─ 很重要!

Linux 上,一般使用者預設**沒有權限**直接存取 Nu-Link 燒錄器。
如果少了這步,燒錄時會看到:

```
Error: hidapi: failed to open device
```

解法是安裝一份 **udev 規則**,讓你的帳號可以存取它。本教材已幫你準備好規則檔
[`common/99-nuvoton-nulink.rules`](../common/99-nuvoton-nulink.rules):

```bash
# 在專案根目錄執行(需要一次 root 權限)
sudo cp common/99-nuvoton-nulink.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
```

然後把 **Nu-Link 的 USB 線拔掉、再插上**,讓新規則生效。

驗證燒錄器有被認到:
```bash
nuvoprog devices
```
看到列出一台裝置就成功了(不再出現 `failed to open device`)。

## 0.5 接上開發板

1. 把 **Nu-Link** 用 USB 線接到電腦。
2. 把 Nu-Link 的燒錄排針接到 N76E003 開發板(通常是 **VDD、GND、DAT(ICPDA)、CLK(ICPCK)、RST** 這幾支)。
   - 很多「Nu-Link + N76E003」的套件出廠就用排針連在一起,直接插 USB 即可。
3. 確認開發板有通電(板上電源 LED 亮)。

## 0.6 編譯與燒錄:每一課都一樣

每個範例資料夾都有 `Makefile`,操作完全一致:

```bash
cd c/01-blink      # 進到某一課(C 版)

make               # 編譯 → 產生 main.hex
make flash         # 編譯(如有需要)並燒錄到開發板
make clean         # 清掉所有編譯產生的檔
```

組語版一模一樣:
```bash
cd asm/01-blink
make flash
```

`make flash` 實際執行的燒錄指令是:
```bash
nuvoprog program -t n76e003 -c FFFFFFFF -a main.hex
```
- `-t n76e003`:目標晶片
- `-c FFFFFFFF`:**設定位元組 (config)**。N76E003 一定要指定,否則 nuvoprog 會
  報 `No configuration bytes specified` 而拒絕燒錄。`FFFFFFFF` 是出廠預設:
  從 APROM 開機、不啟用任何保護鎖,初學階段用這個就對了。
- `-a main.hex`:要燒進 APROM(程式區)的檔案

> nuvoprog 預設燒完會**自動回讀比對 (verify)**,比對通過才算成功。所以只要
> `make flash` 沒有報錯,就代表程式已正確寫進晶片。燒完會自動重置、立刻開始跑。

## 0.7 背後發生了什麼?(編譯流程)

了解這條流水線,出錯時才知道卡在哪一關:

**C 版:**
```
main.c --[sdcc]--> main.ihx --[packihx]--> main.hex --[nuvoprog]--> 晶片
         編譯                整理格式                  燒錄
```

**組語版:**
```
main.asm --[sdas8051]--> main.rel --[sdld]--> main.ihx --[packihx]--> main.hex --> 晶片
           組譯                      連結                  整理格式
```

- `.ihx` / `.hex` 都是 **Intel HEX** 格式,裡面是「要燒到哪個位址、燒什麼位元組」的純文字。
- 這些指令都寫在 `common.mk` 裡了,平常你只要記得 `make` 和 `make flash`。

## 0.8 常見問題 (FAQ)

**Q：`make flash` 出現 `hidapi: failed to open device`?**
A：udev 規則沒裝好,或插上燒錄器前規則還沒生效。回到 0.4,裝好規則後把 USB 重新插拔。

**Q：出現 `No configuration bytes specified in image or config parameter`?**
A：N76E003 燒錄一定要帶設定位元組。本教材的 Makefile 已自動加上 `-c FFFFFFFF`;
如果你是手動下 `nuvoprog` 指令,記得補這個參數。

**Q：找不到 `nuvoprog` 指令?**
A：`~/go/bin` 沒加進 PATH。見 0.3。或直接用完整路徑 `~/go/bin/nuvoprog`。

**Q：燒錄時找不到晶片 / target not found?**
A：檢查 Nu-Link 與開發板的 5 條線(VDD/GND/DAT/CLK/RST)有沒有接好、板子有沒有通電。

**Q：程式燒進去了,但 LED 不如預期(該亮時不亮)?**
A：可能是你的板子板載 LED 是「低電位點亮」。把範例裡的 `LED_ON`/`LED_OFF` 對調,或改用麵包板外接 LED。
