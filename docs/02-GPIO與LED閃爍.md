# 第 02 章:GPIO 與 LED 閃爍(對應第 1 課)

> 對應範例:[`c/01-blink`](../c/01-blink/) 與 [`asm/01-blink`](../asm/01-blink/)
> 這是你的第一支微控制器程式。目標:讓一顆 LED 一亮一滅地閃爍。

---

## 2.1 這一課要做什麼

讓接在 **P1.4** 腳位上的 LED **每隔約 0.3 秒** 亮滅一次。

雖然看起來很簡單,但它包含了控制微控制器最核心的三個動作:

1. **設定** 一支腳為「輸出」模式
2. **輸出** 高電位 / 低電位
3. **延時**(等一段時間)

學會這三件事,你就跨出最重要的第一步了。

---

## 2.2 電路:LED 怎麼接?

LED(發光二極體)是有方向性的:**長腳是正極 (+),短腳是負極 (−)**。電流要從正極流向負極才會亮。而且一定要**串一顆電阻**限制電流,否則 LED 會燒掉。

本教材預設接法(用麵包板外接一顆 LED):

```
   P1.4 ----[ 220Ω 電阻 ]---->|---- GND
                            (LED)
```
`>|` 是 LED:左邊接電阻(長腳/正極),右邊接 GND(短腳/負極)。

- 當 P1.4 輸出 **高電位(約 3.3V)**:電流從 P1.4 流出 → 經電阻 → 經 LED → 回到 GND,**LED 亮**。
- 當 P1.4 輸出 **低電位(0V)**:兩端沒有電位差,**LED 滅**。

> 💡 **如果你用開發板上「內建的 LED」**:很多板子的內建 LED 是接成「低電位才亮」(腳位接 LED 負極,正極接電源)。如果你照程式跑發現「該亮時不亮、該滅時才亮」,就是這個原因 —— 把範例裡的 `LED_ON` 和 `LED_OFF` 對調即可。這一點在第 1 課 README 也會再提醒。

## 2.3 為什麼要先設定「模式」?

還記得第 01 章說的:每支腳可以是輸入、輸出等好幾種模式。開機時 N76E003 的腳位預設是 **準雙向 (quasi-bidirectional)** 模式 —— 這種模式輸出高電位時「拉高」的能力很弱,驅動 LED 可能偏暗或不穩。

所以我們把它改成 **推挽輸出 (push-pull)**:這種模式輸出高/低電位都很有力,最適合驅動 LED。

設定方式(第 01 章的表格):推挽 = `PxM1` 該位 = 0、`PxM2` 該位 = 1。對 P1.4:

```c
P1M1 &= ~(1 << 4);   // 把 P1M1 的第 4 位清成 0
P1M2 |=  (1 << 4);   // 把 P1M2 的第 4 位設成 1
```

### `(1 << 4)` 和 `&=`、`|=` 是什麼?

這叫 **位元運算 (bitwise operation)**,是嵌入式程式的家常便飯,務必弄懂:

- `1 << 4` 代表把二進位的 `1` 向左移 4 位 → `0001 0000`(只有第 4 位是 1)。
- `暫存器 |= (1 << 4)` → 把第 4 位**設成 1**,其他位保持不變。(OR 運算)
- `暫存器 &= ~(1 << 4)` → 把第 4 位**清成 0**,其他位保持不變。(`~` 先反相成 `1110 1111`,再 AND)

> **為什麼不直接寫 `P1M2 = 0x10;`?** 因為那樣會把其他 7 支腳的設定也一起蓋掉!用 `|=`、`&=` 只動我們要的那一位,是好習慣。

## 2.4 輸出高/低電位:操作單一位元

設好模式後,控制亮滅就很簡單。因為 8051 支援「位元定址」,`P14` 這個名字(在 `N76E003.h` 裡定義)直接對應 P1 的第 4 位:

```c
P14 = 1;   // P1.4 輸出高電位 → LED 亮
P14 = 0;   // P1.4 輸出低電位 → LED 滅
```

在組合語言裡,對應的是 `setb`(set bit,設為 1)和 `clr`(clear,清為 0)兩個指令:

```asm
setb  P14      ; P1.4 = 1
clr   P14      ; P1.4 = 0
```

> 這就是 8051 控制 IO 的優雅之處:一個 bit 對一支腳,可以單獨操作,不會動到旁邊的腳。

## 2.5 延時:讓眼睛看得見

如果不延時,程式會以每秒幾百萬次的速度狂切亮滅,你只會看到 LED「一直半亮」。所以要在亮、滅之間**等一下**。

這一課我們用最原始的方法:**讓 CPU 空轉**。寫兩層巢狀 `for` 迴圈,什麼事都不做,純粹消耗時間:

```c
volatile unsigned int i, j;
for (i = 0; i < 300; i++)
    for (j = 0; j < 120; j++)
        ;
```

- `volatile` 很重要:它告訴編譯器「別自作聰明把這個空迴圈刪掉」。沒有它,編譯器最佳化後延時可能消失。
- 圈數(300、120)是**湊出來的概略值**。因為 N76E003 是 1T、跑 16MHz,你可能需要調整數字才能得到想要的速度。

> ⚠️ **這種延時的缺點:** ①不精準(溫度、編譯器最佳化都會影響);②延時期間 CPU 完全不能做別的事。第 3 課我們就用 **計時器 (Timer)** 來解決這兩個問題,那才是專業做法。這一課先求「看得到會動」。

## 2.6 主程式的骨架:`while(1)`

```c
void main(void)
{
    gpio_init();        // 開機只做一次:設定腳位

    while (1)           // 之後永遠重複
    {
        LED = LED_ON;
        delay();
        LED = LED_OFF;
        delay();
    }
}
```

這是**幾乎所有微控制器程式的共同長相**:

- `main` 開頭做一次性的「初始化 (init)」—— 設定腳位、計時器、串列埠等。
- 然後進入 `while(1)` 無窮迴圈,反覆做事。這個迴圈常被稱為 **主迴圈 (main loop)**。

絕對不要讓 `main` 自然結束(對微控制器來說,「結束」沒有意義,行為也不可預期)。

## 2.7 組語版在做一模一樣的事

打開 [`asm/01-blink/main.asm`](../asm/01-blink/main.asm),你會發現它和 C 版**步驟完全對應**,只是用更底層的語言表達:

| 做的事 | C 語言 | 組合語言 |
|--------|--------|----------|
| 設 P1.4 推挽 | `P1M1 &= ~(1<<4); P1M2 \|= (1<<4);` | `anl P1M1,#0xEF` / `orl P1M2,#0x10` |
| LED 亮 | `P14 = 1;` | `setb P14` |
| LED 滅 | `P14 = 0;` | `clr P14` |
| 延時 | `for` 空迴圈 | `djnz` 迴圈 |
| 主迴圈 | `while(1){...}` | `sjmp loop` |

**對照著看**,你會很快發現:C 語言其實就是把這些組語動作「包裝成人看得懂的樣子」。學會對照,兩邊的理解都會更深。

- `anl` = AND(對應 C 的 `&`),用來清除某些位元
- `orl` = OR(對應 C 的 `|`),用來設定某些位元
- `djnz` = Decrement and Jump if Not Zero(減 1,不為 0 就跳)—— 這是組語做迴圈最常用的指令
- `sjmp` = Short Jump,無條件跳回去,形成無窮迴圈
