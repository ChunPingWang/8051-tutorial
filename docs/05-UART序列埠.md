# 第 05 章:UART 序列埠(對應第 4 課)

> 對應範例:[`c/04-uart`](../c/04-uart/) 與 [`asm/04-uart`](../asm/04-uart/)
> 目標:讓 N76E003 透過「序列埠」把文字送到電腦螢幕上。這是最實用的**除錯工具**。

---

## 5.1 為什麼要學 UART?

微控制器沒有螢幕,程式出錯時你看不到裡面發生什麼事。UART 就是它的「嘴巴」:
把變數的值、執行到哪一步等訊息,用一條線送到電腦,你在終端機上就能看到。

**學會 UART,等於學會了 `printf` 除錯法。** 這會讓你之後每一個專案都受用。

UART 也是很多模組(藍牙、GPS、Wi-Fi 模組)的溝通方式,應用非常廣。

---

## 5.2 UART 是怎麼傳資料的?

UART(通用非同步收發)用**一條線**一位一位地把資料送出去。重點名詞:

- **TXD**:傳送腳(晶片的嘴巴)。N76E003 的 UART0 TXD 在 **P0.6**。
- **RXD**:接收腳(晶片的耳朵)。在 **P0.7**。這一課只示範「送」,RXD 可先不接。
- **鮑率 (baud rate)**:每秒傳幾個位元。**兩邊(晶片和電腦)必須設一樣**,否則收到亂碼。常見 9600、115200。
- **資料格式**:本教材用最常見的 **8N1** = 8 個資料位元、No(無)同位檢查、1 個停止位元。

> 「非同步」的意思是沒有另外一條時脈線,全靠雙方「講好的鮑率」各自計時。所以鮑率設錯 = 雞同鴨講。

---

## 5.3 鮑率是怎麼產生的?

UART 需要一個穩定的節拍器來決定「每一位持續多久」。8051 傳統上用 **Timer1** 當這個節拍器:
讓 Timer1 以固定速率一直溢位,UART 每收到若干次溢位就送 1 位。

N76E003 的鮑率公式(當 SMOD=1 倍速、T1M=1 讓 Timer1 吃滿 16MHz 時):

```
baud = Fsys / ( 16 × (256 − TH1) )
```

要 **9600**:
```
256 − TH1 = 16,000,000 / (16 × 9600) ≈ 104
TH1 = 256 − 104 = 152 = 0x98
```
實際得到約 9615 bps,和 9600 差 0.16%,UART 可容忍(通常容許 ±2~3%),非常可靠。

這就是範例裡 `TH1 = 0x98;` 的由來。

> 為什麼不用 115200?在 16MHz 下用 Timer1 算 115200 會有約 3.5% 誤差,比較容易出錯。
> 想要更高又精準的鮑率,可以改用 N76E003 的 **Timer3** 當鮑率產生器(把 `BRCK` 設為 1),這是進階主題。

## 5.4 初始化 UART 的步驟

對照範例程式,初始化做了這幾件事:

```c
P0M1 &= ~((1<<6)|(1<<7));   // ① P0.6/P0.7 設準雙向(UART 腳位標準設定)
P0M2 &= ~((1<<6)|(1<<7));

SCON  = 0x50;    // ② UART0 模式1(8 位元),REN=1 允許接收
TMOD &= ~0xF0;   // ③ Timer1 當鮑率產生器:模式2(8 位元自動重載)
TMOD |=  0x20;
PCON  |= 0x80;   // ④ SMOD=1,鮑率加倍
CKCON |= 0x10;   // ⑤ T1M=1,Timer1 吃滿 16MHz
T3CON &= ~0x20;  // ⑥ BRCK=0,鮑率時脈來源選 Timer1
TH1 = 0x98;      // ⑦ 重載值 → 9600
TL1 = 0x98;
TR1 = 1;         // ⑧ 啟動 Timer1
```

看起來步驟多,其實就是:**設腳位 → 設 UART 模式 → 設好當節拍器的 Timer1 → 開跑**。

## 5.5 送出一個字元:SBUF 與 TI

送資料的核心只有三行:

```c
void uart_putc(char c)
{
    SBUF = c;          // 把字元丟進「傳送緩衝器」,硬體會自動開始一位一位送
    while (!TI)        // 等「傳送完成」旗標 TI 變成 1
        ;
    TI = 0;            // 旗標要自己清 0,否則下次會以為已經送完
}
```

- `SBUF`:一寫進去,硬體就開始把它送出去。
- `TI`(Transmit Interrupt flag):硬體送完一個字元後會把它設成 1。我們用 `while(!TI)` 等它。
- **清旗標是初學者最常忘的**:`TI` 不會自己歸零,要手動 `TI = 0`。

有了 `uart_putc`,送字串就是一個字元一個字元送:

```c
void uart_puts(char *s) { while (*s) uart_putc(*s++); }
```

## 5.6 組語版的差異:字串放在哪?

C 裡的字串常數,編譯器幫你放進程式記憶體 (CODE)。組語就要自己處理:

```asm
msg:
    .ascii "Hello from N76E003!"
    .db    0x0D, 0x0A, 0x00        ; \r \n 和結尾的 0
```

然後用 **`movc A, @A+DPTR`** 把字元一個一個從 CODE 讀出來(`DPTR` 是指向字串的 16 位元指標):

```asm
puts:
    clr   A
    movc  A, @A+DPTR     ; 讀 DPTR 指到的字元
    jz    puts_done      ; 讀到 0 就結束
    lcall putc
    inc   DPTR           ; 指標往後移
    sjmp  puts
puts_done:
    ret
```

這正好讓你看懂 C 的字串在底層是怎麼一回事:**一塊放在程式記憶體、以 0 結尾的位元組陣列**。

## 5.7 在電腦上看輸出

把 USB-TTL 轉接器接好(`P0.6 → RX`、`GND → GND`),插上電腦後會多出一個序列埠裝置(通常是 `/dev/ttyUSB0`)。用任一終端機程式打開它,鮑率設 **9600**:

```bash
picocom -b 9600 /dev/ttyUSB0
# 或
screen /dev/ttyUSB0 9600
# 或
minicom -D /dev/ttyUSB0 -b 9600
```

你應該會看到類似:
```
Hello from N76E003! (count=0)
Hello from N76E003! (count=1)
Hello from N76E003! (count=2)
...
```

> 看到亂碼?九成是鮑率設錯,或接線接到 TXD↔TXD(應該是晶片 TXD 接轉接器 RX)。

## 5.8 C 與組語對照

| 做的事 | C 語言 | 組合語言 |
|--------|--------|----------|
| 送一個字元 | `SBUF = c;` | `mov SBUF, A` |
| 等送完 | `while(!TI);` | `jnb TI, $` |
| 清旗標 | `TI = 0;` | `clr TI` |
| 走訪字串 | `while(*s) ...s++` | `movc A,@A+DPTR` / `inc DPTR` |
