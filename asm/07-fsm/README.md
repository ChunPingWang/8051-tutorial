# 第 7 課:狀態機 ─ 行人穿越號誌(組語版)

> 這一課的主角是 **C 版**([`../../c/07-fsm/`](../../c/07-fsm/))—— 它教的是**程式架構**,
> 還附了電腦模擬器與單元測試。這個組語版是**選修**:讓你看見狀態機在機器層面長什麼樣。
> 建議先把 C 版與 [`../../docs/11-狀態機.md`](../../docs/11-狀態機.md) 讀完再看這裡。

## 兩個版本,自己選一個

| 檔案 | 功能 | 指令行數 | 程式大小 | 適合誰 |
|------|------|:---:|:---:|------|
| [`main.asm`](main.asm) | **精簡版**:5 顆 LED + 按鈕 | 124 | **273 bytes** | 想專心看「狀態機的骨架」 |
| [`main_full.asm`](main_full.asm) | **完整版**:再加 UART 紀錄 + 蜂鳴器 | 188 | **618 bytes** | 想看功能與 C 版完全對等 |

> 參考:C 版編起來是 **2477 bytes**。組語精簡版只有它的 **1/9** —— 這就是組語的賣點,
> 代價是你得自己管每一個位元組。

**先讀 `main.asm`**(骨架),看懂之後再看 `main_full.asm`(它只是多了 UART 與蜂鳴器)。

## 編譯與燒錄

```bash
# 精簡版(預設)
make                          # 產生 main.hex
make flash

# 完整版
make TARGET=main_full         # 產生 main_full.hex
make TARGET=main_full flash

make clean                    # 兩個版本的產物一起清掉
```

## 🖥 沒有開發板?用 ucsim 在電腦上跑這個 HEX

SDCC 附帶 8051 指令級模擬器 `s51`,可以直接執行上面編出來的 `main.hex`:

```bash
make
printf 'step 1 ms\nset bit 0x00 1\nstep 55 s\ndump sfr 0x90 0x90\nquit\n' \
  | s51 -t 51 -X 16M -c - main.hex
```

`set bit 0x00 1` 是直接把 `request`(行人請求)位元設起來,等於「按過按鈕了」。
`dump sfr 0x90 0x90` 則是看 P1 —— 五顆 LED 的狀態就在這個位元組裡。

⚠️ **模擬器的時間會慢 12 倍**,原因與完整用法見
[`../../docs/07-開發與測試流程.md`](../../docs/07-開發與測試流程.md) 的 §7.5。

## 三個「C 換成組語」的關鍵對照

| C 版 (`fsm.c`) | 組語版 | 說明 |
|---|---|---|
| `switch (m->state)` | **跳躍表**:`rl A` → `jmp @A+DPTR` → 一串 `ajmp` | 狀態編號 ×2 當索引,直接跳進去 |
| `fsm_outputs()` 逐欄填 struct | **查表**:`movc A,@A+DPTR` 取出一個燈號遮罩 | 一個位元組就是五顆 LED 的開關,**組語反而比 C 乾淨** |
| `if (m->ticks >= T_...)` | **倒數到 0**:`mov A,ticks` / `jnz` | 省掉整個 16 位元比較 |
| `if (next != state) { ...; ticks = 0; }` | `enter_state:` 單一進入點 | 「進入動作」只寫一次 |

## 兩個讓組語變簡單的設計決定

這個組語版刻意和 C 版有兩處不同,**不是偷懶,是為了讓組語好寫好讀**:

1. **tick 從 100ms 改成 125ms**
   最長的狀態 8 秒 = 64 個 tick,於是**所有計時都塞得進一個位元組** ——
   16 位元加減與比較全部消失。整台狀態機只用 **2 bytes RAM + 4 個位元**。
   而且 0.5 秒剛好 = 4 個 tick(2 的次方),閃爍相位可以直接測 `ticks` 的 bit2,
   不必做除法(C 版用的 `%` 在 8051 上要呼叫函式庫)。

2. **計時改成「倒數」而不是「累加」**
   C 版是 `ticks++` 再比較;組語改成載入後往下減,時間到就是 `ticks == 0`,
   一條 `jnz` 判斷完畢。

各狀態的 tick 數都在 `dur_table`:40 / 24 / 64 / 40 / 16(= 5.0 / 3.0 / 8.0 / 5.0 / 2.0 秒)。

## 完整版多出來的三個技巧

1. **狀態名稱字串表**:每筆**固定 16 bytes**,所以「索引 × 16」只要一條 `swap A`
   (把 A 的高低 4 位互換)。⚠️ 改名字時記得重算補零的個數,不然印出來會錯行。
2. **DPTR 加偏移**:DPTR 是 `DPH`/`DPL` 兩個 SFR 湊的,要自己做 16 位元加法
   (`add A,DPL` → `mov DPL,A` → `clr A` → `addc A,DPH` → `mov DPH,A`)。
3. **兩個計時器各司其職**:Timer0 管 1ms 時間基準、Timer1 管 UART 鮑率。
   所以 `TMOD` 要用 `anl`/`orl` 分別設高低 4 位,**不能用 `mov` 整個蓋掉**。

## 預期結果

1. 開機:車道綠燈 + 行人紅燈(P1 = `0x68`)。
2. 綠燈未滿 5 秒時按按鈕 → 燈不變,但請求被記住;滿 5 秒自動切黃燈。
3. 綠燈已滿 5 秒時按按鈕 → 立刻切黃燈。
4. 之後自動跑完:黃燈 3 秒 → 行人綠燈 8 秒 → 行人綠燈每 0.5 秒閃爍 5 秒 → 全紅 2 秒 → 回綠燈。
5. 流程中按按鈕一律無效。
6. 完整版另外會有蜂鳴器聲(通行時慢嗶、催促時急嗶)與 UART 紀錄:
   ```
   === N76E003 Pedestrian Crossing (ASM) ===
   Press P1.5 to request crossing
   -> VEH GREEN
   BTN: recorded
   -> VEH YELLOW
   -> PED WALK
   BTN: ignored
   -> PED FLASH
   -> ALL RED
   -> VEH GREEN
   ```
   > 狀態名稱刻意用英文:中文一個字佔 3 bytes (UTF-8),4 個字 12 bytes,
   > 補零的算術很容易出錯;英文也不挑終端機編碼。

## 要注意的坑

| 症狀 | 原因 |
|------|------|
| 按鈕按了沒反應 | `update_outputs` 寫 P1 時忘了 `orl A,#0x20` —— 把按鈕腳拉低了,準雙向腳就讀不到按下 |
| 狀態亂跳 / 跳到奇怪的地方 | 跳躍表的索引算錯(`ajmp` 一筆 2 bytes,所以要 ×2),或程式長到跨出 `ajmp` 的 2KB 分頁 |
| 時間全部不對 | ISR 忘了重新裝填 `TH0`/`TL0`(模式 1 不會自動重載) |
| 完整版的 UART 是亂碼 | `TMOD` 被 `mov` 整個蓋掉,把 Timer1 的模式清掉了 |
| 印出來的狀態名稱錯行 | `name_table` 有一筆不是剛好 16 bytes |
